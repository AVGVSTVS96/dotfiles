# Cleanup unnecessary comments and follow self documentation standards

## Standards

- Comments should document why something is done, not what it is done
- Code should be self documenting, comments should be used when decisions are not obvious
- Comments should be concise and to the point, only explaining the why, not the what
- Comments should be removed when they do not follow the aforementioned standards

## Process

1. Review all code files and identify any comments that do not follow the standards
2. Remove the unnecessary comments
3. Review the code files again and ensure that all comments follow the standards
4. If necessary, add comments to explain the why, not the what
5. Consider adding doc strings to functions and classes to improve self-documentation where valuable
6. Repeat the process until all code is self-documenting without unnecessary comments

## After Cleanup

1. Review the code files to ensure all code is adequately self-documenting
2. Make suggestions for improvements to code naming and structure to improve clarity and readability
3. Do research to ensure suggestions are appropriate and cohesive with the rest of the codebase
4. Provide a list of your suggestions for improvements to codebase naming and structure
